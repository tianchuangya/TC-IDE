# 已知问题

本文件只记录**当前代码真实存在**的限制，避免把"计划中"写成"已完成"。
TC-IDE 尚未发布正式版本，也尚未完成 Windows 实机验收。

## 必须实机确认（没有 Windows 设备无法完成）

- 高 DPI、多显示器、窗口最大化/缩放下的布局与文字清晰度。
- 中文 IME 在编辑器、弹出终端、AI 提问框中的候选窗与组合行为。
- 系统剪贴板在拖选、`Ctrl+Shift+C`、粘贴大段文本时的表现。
- 弹出终端的滚动、选择、复制与关闭顺序；关闭 IDE 后是否残留 `powershell.exe`。
- Build/Run、ZIP/MSIX 打包在真实项目上的耗时与失败信息可读性。
- 新增的关系图折叠、标签页、脏状态确认、AI 请求与格式化/调试动作。
- 代码字形宽度已改为 DirectWrite 实测，但**尚未在真机对比**光标与选区是否完全对齐。

## 功能缺口

- **编辑器文本模型**：仍是 `Vec<String>`，没有 rope/piece table、大文件虚拟化和水平滚动；
  超大文件会变慢。
- **LSP**：协议层（分帧、请求、解析）已在 `lsp_core` 中实现并有单元测试，但还没有接入
  stdio 传输层，因此补全、诊断、跳转、引用、重命名、悬停文档尚未在界面上生效。
- **DAP**：只有"启动适配器命令"（debugpy/lldb-dap/dlv）与 PATH 探测，没有断点、调用栈、
  变量面板等调试界面。
- **Tree-sitter**：语义关系仍是正则与启发式；声明/调用的误判只能靠 `declare/ref/weak` 标记弱化。
- **扩展安装**：下载、校验、解包、卸载命令与运行时缓存清单都已实现，但目录需要用户自己提供
  （`<项目>/.tc-ide-catalog.conf`），仓库不会内置编造的 URL 与校验和。
- **AI**：请求、流式输出、超时、取消与错误说明已接入，但回答显示在终端里，
  还没有独立的聊天面板与会话历史。
- **macOS**：`macos_app.rs` 仍是隔离入口，没有 Cocoa/CoreText/PTY/面板实现。
- **Linux**：没有会话恢复与运行时缓存清单；`windows_app.rs` 与 `linux_app.rs` 仍偏大，
  尚未拆分模块。
- **关系图**：大项目缺少后台增量索引与聚类；视口裁剪与节点预算是有的。
- **视觉细节**：文件树折叠仍是旋转箭头而非行位置弹簧；多字符粘贴/撤销的动画仍按单字符处理；
  背景图只有数值调节，没有可视化裁剪框；可点击控件缺少统一的悬停/按下/禁用状态；
  设置与扩展面板的部分文案尚未完整中文化。
- **ConPTY 网格**：面板关闭时仍按完全展开的几何上报行列，属有意为之（避免 shell 看到 1 行）。

## 工程约束

- Windows 代码只能在 Linux 上做**类型检查**（`cargo check --target x86_64-pc-windows-msvc`）
  与 Clippy，不能替代真机行为验证。
- 发布工作流只能手动触发；在项目所有者说"正式开始"之前不会创建标签或 Release。
- AppImage 步骤依赖联网下载 appimagetool，失败时不会阻断发布，但产物会缺失（文件清单会说明）。
